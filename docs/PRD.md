## 1 背景与目标

### 1.1 背景

中小机电研发团队在研发过程中会产生大量彼此关联的数据：需求、物料参数、BOM、供应商、库存批次、采购单、测试记录、ECN 变更以及散落在 Git 仓库与本地文件中的图纸、代码和文档。当前这些信息通常分散在 Excel、邮件和个人电脑中，缺乏统一的关联主线，导致：

- 追溯困难：当客诉、质量问题或合规审计发生时，无法快速回答"这个样机/批次为什么这么设计、用了谁的料、测过什么、变更过什么"。
- 变更失控：ECN 发起后，难以准确圈定受影响的 BOM 节点、库存批次、在途采购单与测试用例。
- 经验流失：物料选型依赖个别工程师经验，缺乏可复用、可审计的候选推荐与理由记录。
- Git 与文件证据脱节：代码提交、图纸版本与业务对象之间没有可追溯的关联。

AI 智能体可以辅助需求提取、物料选型和全链路追溯，但若缺乏审计与人工确认机制，容易产生"看似合理却无法溯源"的结论（幻觉）。因此本平台的核心不是"让 AI 自动决策"，而是"让 AI 产出**可追溯、可审计、需人工确认**的建议"。

### 1.2 目标

- 建立以 **TraceLink 追溯元数据**为主线的单租户轻量平台，统一管理需求、参数、BOM、物料、供应商、库存批次、采购单、测试、ECN、文件与 Git 提交。
- 对 Git 仓库与文件仅做**只读关联**，不发生任何写回。
- 提供三类可审计智能体：Requirement Agent、BOM/选型 Agent、Traceability Agent，辅助需求录入、物料选型与全链路追溯。
- 凡经 LLM 推理的智能体调用均产生 **AgentRun 审计记录**（输入、输出、引用、确认人）；纯数据查询不产生 AgentRun（R1），实现可审计、可追溯、防幻觉。
- 关键计算（BOM 展开、齐套、ECN 影响、LLM JSON 校验）具备 golden tests 保障。
- 演示环境可支撑 **15 分钟完整端到端演示**。

### 1.3 成功判据

- 任一演示序列号可一键反查"需求 → BOM → 物料批次 → 采购单 → 测试 → ECN → Git 提交"完整链路。
- 每一次智能体输出均可追溯到输入、引用与人工确认人，且未经确认的建议不进入正式数据。
- 演示数据集与场景满足 `docs/demonstration_project_requirements.md` 的全部验收要点。

## 2 非目标

以下内容明确**不在本产品范围内**：

- 对接真实 ERP / MES / 供应商 API。
- CAD / EDA 文件的深度解析（仅做文件只读关联，不做几何或网表解析）。
- 多租户支持与复杂 RBAC（本产品为单租户；权限沿用简单账号与角色，不做细粒度对象级 RBAC 体系）。
- 自动下单、自动发邮件、自动修改 BOM 等任何自动化写操作。
- 自主多智能体循环（智能体之间不进行无人工介入的自主协作循环）。
- 模型微调（仅使用通用模型 + 提示工程与规则评分）。

## 4 核心流程

### 4.1 流程 A：需求录入（Requirement Agent）

1. 用户上传客户邮件 / PRD / SOR 文件。
2. Requirement Agent 解析文本，抽取候选需求卡。
3. 系统展示候选需求卡（演示要求 ≥ 5 张），每张卡附来源引用与置信信息。
4. 用户逐张**人工确认**（采纳 / 编辑后采纳 / 拒绝）。
5. 确认后的需求写入正式需求实体，并写入对应 TraceLink 追溯链。
6. 全过程记录 AgentRun（输入、输出、引用、确认人）。

### 4.2 流程 B：物料选型（BOM/选型 Agent）

1. 用户输入选型约束参数，如电压、电流、温度、IP 等级、成本。
2. Agent 按参数过滤 + 规则评分生成候选，并由 LLM 输出可读解释。
3. 系统展示候选物料（演示要求 ≥ 3 个），每项含**停产状态、交期、成本、替代理由**与引用。
4. 用户**人工确认**候选，可形成初版 BOM。
5. 确认结果写入 BOM 与 TraceLink；全过程记录 AgentRun。

### 4.3 流程 C：全链路追溯（Traceability Agent）

1. 用户输入样机序列号 / 批次号。
2. Agent 反查需求、图纸/文件、物料、采购、测试、ECN 与 Git 提交。
3. 系统返回完整追溯链，每个节点**带引用**（来源记录与证据）。
4. 用户可沿链路下钻查看原始对象；全过程记录 AgentRun。

### 4.4 流程 D：ECN 影响分析

1. 用户发起 ECN，指定变更对象与变更内容。
2. 系统分析并列出受影响的 **BOM 节点、库存批次、在途采购单、测试用例**。
3. 影响结果需人工确认后固化为 ECNImpact。

### 4.5 流程 E：工单齐套分析

1. 用户创建工单（WorkOrder）。
2. 系统展开 BOM，比对库存与在途到货。
3. 输出**缺料清单、最晚到货日、替代可行项**。

### 4.6 只读与审计横切流程

- Git/文件任何操作均为只读，禁止 `push`/`commit`/`checkout`/`reset` 等写操作。
- LLM 调用统一在 AgentRun 落库；纯数据查询不产生 AgentRun（R1）。

## 5 功能需求

### 5.1 基础与实体管理

- **FR-001 单租户登录**：系统必须提供单租户账号登录，登录后方可访问业务数据。
- **FR-002 项目管理**：系统必须支持创建、查看、编辑项目，并允许在各项目下组织业务数据。
- **FR-003 需求管理**：系统必须支持需求的创建、查看、编辑、查询；每条需求含来源、状态与参数。
- **FR-004 参数管理**：系统必须支持物料参数（PartParam）与需求参数（RequirementParam）的维护与关联。
- **FR-005 BOM 管理**：系统必须支持 BOM 及 BOM 明细（BomItem）的创建与查看，支持层级展开。
- **FR-006 物料管理**：系统必须支持物料（Part）的创建、查看、编辑，含停产状态与关键参数。
- **FR-007 供应商管理**：系统必须支持供应商（Supplier）及其可供物料关系（SupplierPart）的维护。
- **FR-008 库存批次管理**：系统必须支持库存批次（InventoryLot）的维护，并可与批次/序列号关联。
- **FR-009 采购单管理**：系统必须支持采购单（PurchaseOrder）的创建与查看，含在途标识与预计到货日。
- **FR-010 测试管理**：系统必须支持测试用例（TestCase）与测试执行记录（TestRun）的维护。
- **FR-011 ECN 管理**：系统必须支持 ECN 的发起、查看与变更影响固化（ECNImpact）。

### 5.2 追溯与只读关联

- **FR-012 文件管理（只读关联）**：系统必须支持将文件（Document）以引用方式关联到业务对象，文件内容只读、不回写源文件。
- **FR-013 Git 提交只读关联**：系统必须支持通过只读方式关联 Git 提交（GitCommit），仅允许 `log`/`show`/`diff`/`ls-tree` 等读取操作，禁止任何写操作。
- **FR-014 TraceLink 追溯元数据**：系统必须提供统一的 TraceLink 追溯元数据表，**所有跨实体关联必须经它承载**（详见第 6 章）。

### 5.3 智能体能力

- **FR-015 Requirement Agent**：系统必须支持上传 PRD/SOR/邮件并抽取候选需求卡，输出须附来源引用；演示场景下候选需求卡 ≥ 5 张。
- **FR-016 BOM/选型 Agent**：系统必须支持输入电压/电流/温度/IP/成本等参数，经"参数过滤 + 规则评分 + LLM 解释"输出候选物料；演示场景下候选物料 ≥ 3 个，每项含停产、交期、成本、替代理由。
- **FR-017 Traceability Agent**：系统必须支持输入序列号/批次/样机，返回"需求→BOM→物料批次→采购单→测试→ECN→Git 提交"完整链路，且每个节点带引用。
- **FR-018 ECN 影响分析**：系统必须支持发起 ECN 并列出受影响的 BOM 节点、库存批次、在途 PO、测试用例。
- **FR-019 工单齐套分析**：系统必须支持创建工单并输出缺料清单、最晚到货日、替代可行项。

### 5.4 人工确认与审计

- **FR-020 人工确认（正式流程）**：所有智能体产出必须经过正式的人工确认流程（候选展示 → 人工确认/编辑后确认/拒绝 → 写入或丢弃），确认前不得进入正式数据与追溯链。此为主流程的**必备环节**，而非异常分支。
- **FR-021 AgentRun 审计**：凡经 LLM 推理的智能体调用均产生 AgentRun 记录（纯数据查询不产生记录，R1），至少包含：输入、输出、引用、确认人、时间。
- **FR-022 防幻觉约束**：智能体输出必须具备可核验引用；无引用或引用不匹配的产出不得进入正式数据；结构化输出需通过 JSON 校验。

## 6 数据约束（TraceLink 中心原则）

### 6.1 核心原则

- **关联通道分层**：**层级 / 包含 / 归属 / 计算强依赖关系使用外键（FK）；跨域、需审计、多对多的追溯关系使用 TraceLink**。TraceLink 是跨域追溯的**唯一权威来源**，外键不构成追溯声明。
- **计算明细例外**：计算明细表（`ECNImpact`）可持临时多态引用，用于计算与展示；经人工确认后必须另写 `TraceLink`，作为唯一审计追溯记录。
- **可追溯**：任一追溯链均可由 TraceLink 记录逐跳还原，直至原始业务对象与证据引用。
- **可审计**：TraceLink 记录必须保留创建人、创建时间、来源智能体（如有）、确认人，任何变更留痕，不做无痕物理删除。

### 6.2 TraceLink 关键字段约束

| 字段 | 说明 |
| --- | --- |
| 源实体类型 / 源实体标识 | 关联起点（如 Requirement、Bom、InventoryLot） |
| 目标实体类型 / 目标实体标识 | 关联终点 |
| 关联类型 | 表达语义（如 derived_from、used_by、tested_by、changed_by） |
| 证据引用 | 指向文件、Git 提交或业务记录，用于防幻觉核验 |
| AgentRun 引用 | 若关联由智能体建议产生，须指向对应 AgentRun（可空） |
| 确认人 / 确认时间 | 人工确认后写入，标识该关联已生效 |
| 创建人 / 创建时间 | 审计留痕 |

### 6.3 只读与不变式

- Git 与文件仅只读：系统中不提供任何写回源仓库或源文件的路径。
- 未经人工确认的智能体关联，不得写入生效状态的 TraceLink。
- 所有计算与追溯结果以数据库记录与引用为准，不依赖模型记忆。

## 7 验收标准

### 7.1 演示数据集

- **AC-001**
  - Given 演示环境完成种子数据初始化
  - When 运行 `scripts/validate_seed.py` 校验演示数据集（`fixtures/demo_seed.json`）
  - Then 校验通过，且数据集包含：1 个项目、20 个物料（Part）、5 个需求（Requirement）、3 个供应商（Supplier）、5 个采购单（PurchaseOrder）、3 个批次/序列（InventoryLot）、2 个 ECN；测试数据分两类清点——10 个测试用例（TestCase）与 12 次测试执行（TestRun）。

### 7.2 需求智能体

- **AC-002**
  - Given 用户已登录并进入项目
  - When 上传客户邮件并触发 Requirement Agent
  - Then 系统生成需求卡，且数量 ≥ 5 张，每张附来源引用。

- **AC-003**
  - Given 系统已生成候选需求卡
  - When 用户执行人工确认
  - Then 确认后的需求进入正式数据并写入 TraceLink，AgentRun 记录含输入、输出、引用、确认人。

### 7.3 选型智能体

- **AC-004**
  - Given 用户输入电压、电流、温度、IP 等级、成本等参数
  - When 触发 BOM/选型 Agent
  - Then 系统推荐 ≥ 3 个候选物料，且每项包含停产状态、交期、成本、替代理由；**每项候选须含非空 `source_refs`**（可核验的来源引用）；若候选是对被排除料（停产 / 不合规）的替代建议，须给出 `replaces_part_id`（被替代料业务编号）与替代理由。

### 7.4 追溯智能体

- **AC-005**
  - Given 存在有效的样机序列号
  - When 用户输入该序列号触发 Traceability Agent
  - Then 系统返回"需求→BOM→物料批次→采购单→测试→ECN→Git 提交"链路，且每个节点带引用；`found` 与 `complete` 为**准正交**维度（`found=false` 时 `complete` 必为 `false`），且 `complete ⇔ missing=[]`（**双向强制**：`missing` 非空则 `complete=false`；`missing=[]` 则 `complete=true`）——根实体不存在时 `found=false` 且 `complete=false`（合法业务结果，非失败）。口径与 `docs/interface_contract.md` §3.1 情形表一致。

### 7.5 ECN 影响

- **AC-006**
  - Given 用户发起一项 ECN
  - When 系统执行影响分析
  - Then 列出受影响的 BOM 节点、库存批次、在途 PO、测试用例；`ECN-001` 的影响面须与 golden test `GT-ECN-001` 的冻结明细一致（`BI-001`、`LOT-DCDC-001`、`PO-001`、`TC-001`、`TC-009`），分析投影**不写回**正式 `BomItem`（正式应用须经人工确认）。

### 7.6 工单齐套

- **AC-007**
  - Given 用户创建工单
  - When 系统执行齐套分析
  - Then 输出缺料清单（含最晚到货日、替代可行项）；**当全部需求均可由可用库存满足时，缺料清单为空**。

### 7.7 只读约束

- **AC-008**
  - Given 用户查看 Git 提交或文件关联
  - When 尝试对 Git / 文件端点执行写方法（POST / PUT / PATCH / DELETE）
  - Then 系统返回 `403`（已认证但禁止）或 `404`（端点不存在），且**目标文件 mtime 与仓库 commit 均无变化**（测试可断言前后对比）。

### 7.8 审计

- **AC-009**
  - Given 经 `/agents/*/run/` 的智能体推理调用
  - When 查看审计记录
  - Then 必存在对应 AgentRun，包含输入、输出、引用、确认人；**不调用 LLM 的纯查询（含 `/trace/serial/<sn>/` 的 `found=false` 短路）不产生 AgentRun**。

## 8 风险与假设

### 8.1 风险

| 风险 | 说明 | 应对方向 |
| --- | --- | --- |
| 模型幻觉 | 智能体可能产出无依据的结论 | 强制引用、JSON 校验、人工确认前置（FR-020/022） |
| 引用失效 | 来源文件或提交被移除导致引用断裂 | 保留引用快照信息，标记失效引用 |
| 只读被绕过 | 误引入写操作导致仓库被改 | 明确禁止写操作，审计与校验只读命令白名单 |
| 人工确认流于形式 | 用户批量无脑确认 | 确认界面突出引用与差异，保留确认人痕迹 |
| 关键计算错误 | BOM 展开/齐套/ECN 影响计算偏差 | D12 golden tests 覆盖 |


### 8.2 假设

- 本产品为单租户内部使用，不存在跨租户数据隔离需求。
- 权限模型保持简单（登录 + 基本角色），复杂 RBAC 明确不做。
- 演示环境可使用 SQLite，正式演示部署使用 PostgreSQL。
- Git 仓库可通过本地路径只读访问，且具备读取权限。
- AI 能力基于通用大模型 + 提示工程与规则评分，不做模型微调。
