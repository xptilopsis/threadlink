# ThreadLink 演示项目需求

> 本文档定义演示环境的**数据规模基线**、**业务场景**与**数据格式约定**，作为 D13「15 分钟可完整演示」的验收依据。

---

## 一、演示数据集规模（数量必须）

演示环境须内置以下种子数据（Mock 数据），数量为**硬性要求**：

| 实体（顶层键） | 数量 | 说明 |
| --- | --- | --- |
| 项目 `projects` | 1 个 | 单租户单项目演示 |
| 用户 `users` | 若干 | 覆盖管理员 / 研发 / 采购 / 测试等角色 |
| 物料 `parts` | 20 个 | 见 2.2 物料多样性约束 |
| 需求 `requirements` | 5 个 | 见 2.1 需求覆盖 |
| 测试用例 `test_cases` | 10 个 | |
| 供应商 `suppliers` | 3 个 | 见 2.3 供应商约束 |
| 采购单 `purchase_orders` | 5 个 | 含在途 PO |
| 库存批次 / 序列 `inventory_lots` | 3 个 | 含样机序列号 `SN-DEMO-001` |
| ECN `ecns` | 2 个 | `ECN-001`、`ECN-002`，见 2.5 |
| 测试执行 `test_runs` | ≥ 10 条 | |
| 追溯元数据 `trace_links` | ≥ 30 条 | 覆盖全部跨域关系 |
| Git 仓库 `git_repos` | 1 个 | 只读 |
| Git 提交 `git_commits` | 3 条 | 关联需求 / BOM 节点 |

| 智能体调用 `agent_runs` | 若干 | 覆盖三类智能体 |

## 二、业务场景与数据约束

### 2.1 需求覆盖

需求参数（`requirement_params`）须覆盖以下选型约束：

- 输入电压：**9–36V DC**
- 额定电流：**≥ 5A**
- 工作温度：**-40 ~ 85°C**
- 防护等级：**IP65**
- BOM 成本：**≤ ¥800**

### 2.2 物料多样性（20 个物料内）

- 至少 **1 个停产物料**（`lifecycle_status` = `eol` / `obsolete`）。
- 至少 **1 个长交期物料**（`lead_time_days` 明显偏长）。
- 至少 **1 个可替代料**（与某物料构成 `replaces` 关系）。

### 2.3 供应商约束

- **3 个供应商**，不得使用真实供应商敏感信息（名称脱敏，如 `供应商A / 供应商B / 供应商C`）。
- `supplier_parts` 关系须包含：**价格、MOQ、交期、生命周期**。

### 2.4 样机全链路追溯

- 样机序列号 **`SN-DEMO-001`** 必须能串起完整链路：

  **需求 → BOM → 物料批次 → 采购单 → 测试 → ECN → Git 提交**

### 2.5 ECN 场景

- **`ECN-001`**：DC-DC 物料替换；须影响 **BOM 节点、库存批次、在途 PO、测试用例**。
- **`ECN-002`**：外壳防护等级从 **IP54 提升到 IP65**。

## 三、演示场景与验收要点

### S1 需求智能体：邮件 → 需求卡
- 输入：上传客户邮件（PRD/SOR/邮件）。
- 期望：生成需求卡 **≥ 5 张**。

### S2 BOM/选型智能体：参数 → 候选物料
- 输入：电压、电流、温度、IP 等级、成本（对齐 2.1）。
- 期望：推荐 **≥ 3 个**候选物料，每个候选含**停产状态、交期、成本、替代理由**。

### S3 追溯智能体：序列号 → 全链路
- 输入：样机序列号 `SN-DEMO-001`。
- 期望：返回完整追溯链 **需求 → BOM → 物料批次 → 采购单 → 测试 → ECN → Git 提交**。

### S4 ECN 影响分析
- 输入：发起 `ECN-001`。
- 期望：列出受影响的 **BOM 节点、库存批次、在途采购单、测试用例**。

### S5 工单齐套分析
- 输入：创建工单。
- 期望：输出 **缺料清单、最晚到货日、替代可行项**。

## 四、数据集顶层键

种子数据以 JSON 组织，须包含以下 **22 个顶层键**：

```
project, users, parts, part_params, suppliers, supplier_parts,
requirements, requirement_params, boms, bom_items, inventory_lots,
work_orders, purchase_orders, test_cases, test_runs, ecns, ecn_impacts,
trace_links, documents, git_repos, git_commits, agent_runs
```

## 五、数据格式约定

| 约定 | 说明 |
| --- | --- |
| ID 稳定 | 使用**字符串编号**且全局稳定，如 `PART-001`、`REQ-001`、`PO-001`；不得使用随机值或自增序号作为对外标识 |
| 日期 | 统一 **ISO8601**（如 `2026-03-05T10:30:00+08:00`） |
| 金额 | 统一**字符串**（如 `"12.50"`），禁止浮点数 |
| 脱敏 | 不得出现真实供应商敏感信息；供应商名称与料号均使用演示占位值 |

**ID 前缀建议**：

| 实体 | 前缀 | 示例 |
| --- | --- | --- |
| 项目 | `PROJ` | `PROJ-001` |
| 用户 | `USER` | `USER-001` |
| 物料 | `PART` | `PART-001` |
| 物料参数 | `PP` | `PP-001` |
| 供应商 | `SUP` | `SUP-001` |
| 供应商-物料 | `SP` | `SP-001` |
| 需求 | `REQ` | `REQ-001` |
| 需求参数 | `RP` | `RP-001` |
| BOM | `BOM` | `BOM-001` |
| BOM 明细 | `BI` | `BI-001` |
| 库存批次 / 序列 | `SN` / `LOT` | `SN-DEMO-001` / `LOT-DCDC-001`（业务编号 = `serial_number`，不使用 `INV`） |
| 工单 | `WO` | `WO-001` |
| 采购单 | `PO` | `PO-001` |
| 测试用例 | `TC` | `TC-001` |
| 测试执行 | `TR` | `TR-001` |
| ECN | `ECN` | `ECN-001` |
| ECN 影响 | `EI` | `EI-001` |
| 追溯元数据 | `TL` | `TL-001` |
| 文件 | `DOC` | `DOC-001` |
| Git 仓库 | `GIT` | `GIT-001` |
| Git 提交 | 提交 SHA | 真实提交 SHA（如 `a1b2c3…`，不使用 `GC`） |
| 智能体调用 | `AR` | `AR-001` |

## 六、只读与审计约束

- **Git / 文件只读展示，不能修改仓库**；文件仅关联不写回。
- **凡经 LLM 推理的智能体调用均产生 AgentRun 记录**（输入、输出、引用、确认人）；纯数据查询不产生 AgentRun。
- 智能体产出的追溯关系须经**人工确认**后方可进入正式追溯链。
