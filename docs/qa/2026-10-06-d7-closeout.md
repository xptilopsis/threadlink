## 五、集成缓冲评估结论（§1）

### 5.1 `replaces`「仅限排除清单内」硬执行

| 维度 | 评估 |
| --- | --- |
| **成本** | 需新增 `FailureReason` 枚举值（如 `out_of_candidates`）→ schema 扩展 + `interface_contract`/`data_dictionary` 四处消费方再同步一轮（D7-R1/R2 刚同步过 `ambiguous`）+ bom_selection 管道新增「在列」校验 + 测试；跨 3–4 文件。 |
| **收益** | 仅提升**解释质量**（`replaces` 建议来源更精确）；**不改变正确性**——清单外但存在的物料建议仍指向真实实体，`approve` 写入的是指向真实物料的 `replaces` `TraceLink`，**不构成幻觉/错误写入**。 |
| **风险** | 硬执行引入**新失败面**（清单外但合法建议被判 `failed` → 人工重回）；「排除清单」边界随 criteria 浮动，可能误杀合理建议。 |

**结论：v1 维持 prompt 约束 + 存在性核验（幻觉编号已由 `verify_references` 拦截）；「在列」硬执行延至 v2。**

### 5.2 `TraceLink` 重复边语义（v1 定稿，无代码）

- **唯一性** = `(project, from_type, from_id, to_type, to_id, relation_type)` **全元组**。
- **现库约束原文**（`traceability/models.py::TraceLink.Meta`）：

  ```python
  models.UniqueConstraint(
      fields=["project", "from_type", "from_id", "to_type", "to_id", "relation_type"],
      name="uq_tracelink_edge",
  )
  ```

  → 与定稿**逐字一致**（核对通过，无偏差）。
- **同元组二次写入** = DB 层拒绝（`IntegrityError`）。
- **approve 流程** = 写入前同元组去重跳过（`agents/bom_selection.py::approve_bom_selection`：`filter(同元组).exists()` → 跳过）。
- **不做跨 run 的确认合并**（同元组只保留一条，二次 approve 不因新 run 更新既有边 `confirmed_by`）。
